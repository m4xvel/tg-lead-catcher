# tg-lead-catcher

Запуск: `/autopilot semi strict polish brief.md`

## 1. Задача

Разработать решение для Telegram, которое по ключевым словам находит сообщения
в выбранных чатах и пересылает их в целевой чат или группу.

Списки целевых чатов (приёмников), чатов для поиска (источников) и ключевых слов
пользователь должен уметь добавлять и удалять **сам, через UI, а не через код**.

Практическая цель — лидогенерация: находить в чатах людей, которым нужна услуга,
и иметь возможность потом их найти по контакту.

## 2. Архитектура

**Гибрид из двух Telegram-подключений:**

- **Userbot** (MTProto, Telethon, вход по номеру телефона) — читает чаты и
  пересылает найденное. Работает от **основного аккаунта пользователя**: смысл
  задачи в чатах, где пользователь уже состоит, включая приватные.
- **Bot API-бот** (aiogram 3, токен от @BotFather) — **только панель управления**.
  Пересылку не делает: Bot API физически не может форвардить из чата, где бота нет.

Доставку в приёмники выполняет userbot. Приёмником может быть любой чат, канал
или «Избранное» — добавлять туда бота не нужно.

- Один пользователь. Мультиарендности нет.
- Стек: **Python**, Telethon + aiogram 3 + SQLite.
- Запуск локальный (Windows), но собрано переносимо: Docker + `.env`,
  переезд на VPS одной командой.
- Папка проекта: `C:\Users\X79\leed`, `git init` в начале.
- Язык интерфейса: **русский**. Таймзона `Europe/Moscow`, настраивается в `.env`.

## 3. Ядро: поиск и пересылка

### 3.1 Матчинг ключевых слов

Плоская схема: **один** список источников, **один** набор ключей и минус-слов,
**один** список приёмников. Всё найденное летит во все приёмники.

Три типа ключей, различаются синтаксисом при вводе:

| Ввод                          | Тип                  | Поведение                                                                                                                                                                                                                                                              |
| --------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ремонт`                  | слово              | совпадает с началом слова по границе слова: ловит «ремонт», «ремонта», «ремонтом», «ремонтник»;**не** ловит внутри слова («авто» не ловит «автора») |
| `"ищу подрядчика"` | точная фраза | несколько слов подряд                                                                                                                                                                                                                                        |
| `re:\d{3}-\d{2}`                | regex                   | валидируется при добавлении; кривой regex отклоняется с понятной ошибкой и**не роняет бота**                                                                                                       |

- Регистр игнорируется, «ё» и «е» эквивалентны.
- **Минус-слова** — отдельный список с тем же синтаксисом. Совпадение минус-слова
  отменяет срабатывание («ремонт» + «вакансия» → не пересылать).

### 3.2 Что считается сообщением

- Ищем в тексте сообщения **и в подписях** к фото/видео/документам.
- Пересылаем сообщение **целиком, с медиа**.
- Альбом (несколько фото одним постом) — целиком, одной группой.
- **Отредактированные сообщения ловим** (лид часто дописывает контакты),
  с дедупом по ID, чтобы не задваивать.
- Источники: группы, супергруппы и каналы. Личные переписки **не** мониторим;
  включается отдельным флагом.

### 3.3 Доставка

Основной способ — **forward**. Если в чате запрещена пересылка
(`ChatForwardsRestrictedError`) — автоматический фолбэк на **копию** текста.
Ни одно срабатывание не теряется.

**Подпись источника обязательна всегда**, отдельным сообщением следом:

```
🔑 ремонт, срочно
👤 Иван П. · @ivan_p · id 123456789
💬 Чат: «Ремонт СПб» · ссылка на оригинал
🕐 27.08.2026 14:32
```

- Если **username отсутствует** — вместо него кликабельная ссылка
  `tg://user?id=...` плюс сам числовой ID.
- Ссылка на оригинал: `t.me/<chat>/<id>` для публичных,
  `t.me/c/<internal_id>/<id>` для приватных.
- **Шаблон подписи редактируется в UI.**

### 3.4 Антидубли и защита от петель

- **Дедуп по сообщению** (chat_id + message_id) — всегда, без отключения.
- **Дедуп по автору и тексту**: если тот же автор с тем же нормализованным
  текстом уже прилетал за последние **7 дней** — второй раз не слать, а в подписи
  к первому дописать «также в: Чат Б, Чат В». Окно настраивается в UI,
  дедуп можно выключить.
- Обязательные защиты: не реагировать на **свои** сообщения, на сообщения
  **ботов** и на **чат-приёмник** (иначе бесконечный цикл).

### 3.5 История и догон

- При старте — **догон пропущенного**: по каждому чату запоминается последнее
  обработанное сообщение, при запуске дочитывается пропущенное.
- При добавлении чата — кнопка **разового сканирования истории**
  («просканировать последние 7 дней»).
- **Предохранитель:** догон не глубже **3 дней** и не более **500 сообщений**
  на чат за раз, с паузами между запросами — иначе флуд-лимиты и блокировка.
  Порог глубины настраивается.

## 4. UI: панель управления внутри Telegram

Всё управление — в Bot API-боте, кнопками и меню. Никаких правок конфигов руками.

### 4.1 Источники (чаты для поиска)

Кнопка «➕ Добавить чат» даёт три способа:

- **«📋 Из моих чатов»** (основной) — userbot отдаёт список групп и каналов,
  где состоит пользователь; бот показывает **постранично по 8** с поиском
  по названию.
- **«↩️ Переслать сообщение»** — бот вытаскивает `chat_id` из форварда.
- **«⌨️ Ввести вручную»** — `@username`, ссылка `t.me/...` или числовой `chat_id`.

Список источников — постранично, у каждого **❌ удалить** и переключатель
**«пауза»** (временно отключить, не удаляя).

### 4.2 Приёмники

Те же три способа **плюс кнопка «💾 Избранное»** (Saved Messages) одним нажатием
— она же приёмник по умолчанию при первом запуске.

При нескольких приёмниках — **дублируем во все**, но каждая доставка это
**отдельная задача в очереди**: если одна группа недоступна (чат удалён, доступа
нет), остальные всё равно получат, а по упавшей приходит уведомление.

### 4.3 Ключевые слова и минус-слова

- Ввод **списком**: пришёл текст в 10 строк — добавились 10 ключей, дубли отсеклись.
- Минус-слова — отдельный раздел с тем же вводом.
- Удаление — кнопкой у каждого элемента.
- Кнопка **«🧪 Проверить»**: вставляешь любой текст → бот отвечает
  «✅ сработало по: ремонт, срочно» / «❌ не сработало» /
  «⛔ заблокировано минус-словом: вакансия».

### 4.4 Статус, статистика, история

- **Тумблер мониторинга ⏸/▶️** — остановить, не выключая программу.
- **Статус**: работает ли, сколько чатов, сколько ключей, что в очереди,
  когда было последнее срабатывание.
- **Статистика** за 7 и 30 дней: сколько сработок, по каким ключам, из каких чатов.
- **«📊 Топ мусорных ключей»** — ключи с наибольшим числом срабатываний,
  чтобы сразу видеть, что засоряет выдачу.
- **История**: последние 50 срабатываний списком со ссылками.
  Полнотекстового поиска не нужно.

### 4.5 Пауза и пропущенное

При снятии паузы бот **спрашивает явно**:
«⏸ Пауза длилась 3 ч 20 мин. Догнать пропущенное? [Да] [Нет]».
Догон при простое программы (п. 3.5) — автоматический, вопроса не задаёт.

### 4.6 Экспорт

Команда `/export` отдаёт настройки (источники, ключи, минус-слова, приёмники)
отдельным JSON — чтобы при переезде на VPS не набивать списки заново.

## 5. Настройка при первом запуске

**Интерактивный мастер-скрипт `setup`**, который проводит по шагам, объясняет,
где взять каждое значение, сам пишет `.env`, сам проводит логин userbot
и в конце проверяет, что всё живо:
«userbot подключен как Иван, бот @xxx жив, доступ у ID 123».

Пользователь получает сам: `API_ID` + `API_HASH` с **my.telegram.org**,
токен бота у **@BotFather**.

**Код подтверждения входа вводится только в терминале**, никогда в переписке
с ботом: код входа не должен оседать в истории чата.
2FA-пароль — там же, в терминале.

**Доступ к панели — только у Telegram ID владельца**, записывается в `.env`
на этапе мастера. Любому другому бот отвечает «Доступ запрещён» и логирует попытку.

Секреты нигде не запрашиваются агентом и не сохраняются в репозиторий.
`.env`, `./data/` и `*.session` — в `.gitignore` до первого коммита.

## 6. Устойчивость

- **Очередь доставки в SQLite** между «нашли» и «переслали»: 3 попытки
  с нарастающей задержкой. Ничего не теряется.
- **Глобальный лимит отправки 20 пересылок/мин** (настраивается), избыток ждёт
  в очереди — при всплеске в 50 совпадений аккаунт не улетает во флуд-лимит.
- **`FloodWaitError`** — спим ровно столько, сколько сказал Telegram, пишем в лог.
- **Смерть сессии** (`AuthKeyUnregistered` и подобное) — бот немедленно пишет
  владельцу «⚠️ Сессия отвалилась, запусти вход заново», мониторинг встаёт
  до починки. Молча стоять нельзя.
- **Автозапуск**: `docker compose` с `restart: unless-stopped`;
  при локальном запуске без Docker — задача в Планировщике Windows на вход в систему.

## 7. Данные

- **SQLite** в `./data/bot.db`, сессия userbot — `./data/*.session`.
  Папка в `.gitignore`, бэкап = копия папки.
- В лог срабатываний пишем: `chat_id`, `message_id`, автор (id / username / имя),
  сработавшие ключи, хеш текста (для дедупа), время,
  и **первые 500 символов текста** — нужны для дедупа по тексту
  и чтобы история читалась без перехода в чат.
- **Ретеншн 90 дней**, дальше автоочистка. Срок настраивается.

## 8. Границы

Явно **не** входит в задачу:

- Мультиарендность (несколько пользователей со своими аккаунтами и списками).
- Веб-панель или десктопное приложение — UI только внутри Telegram.
- Правила/профили: схема плоская, один набор ключей на всё.
- Морфологический анализ (pymorphy и подобное) — матчинг по началу слова
  плюс минус-слова закрывают задачу.
- Полнотекстовый поиск по истории срабатываний.
- Отдельный номер под userbot — работаем с основного аккаунта.
- Автоматические ответы лидам, рассылки, вступление в чаты — решение только
  читает и пересылает.
