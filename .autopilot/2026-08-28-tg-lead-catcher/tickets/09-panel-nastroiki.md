## Что должно заработать

Новый раздел панели «⚙️ Настройки» (кнопка в главном меню, `panel/__init__.py`/`panel/keyboards.py` — посмотри, как уже собрано главное меню в тикете 05, добавь туда пункт) с редактированием шести уже существующих настроек — каждая уже читается кодом из `SettingsRepo`, просто никто их не может поменять иначе как прямой записью в БД:

- **Личные чаты** (`monitor_all_dm`, R26) — тумблер вкл/выкл.
- **Шаблон подписи** (`card_template`, R31) — текстовый ввод нового шаблона (тот же формат, что уже используется в `userbot/deliver.build_card` — плейсхолдеры вроде `{keywords}`/`{author}`/`{chat}`/`{time}`, посмотри, как их называет `build_card`, и покажи текущий шаблон перед вводом нового).
- **Окно дедупа и его отключение** (`dedup_window_days`, `dedup_enabled`, R33) — число дней + отдельный тумблер вкл/выкл.
- **Глубина догона** (`scan_days`, `scan_msgs`, R37) — числа; учти, что `HARD_MSG_CAP=500` в `userbot/catchup.py` — верхний предохранитель, задаваемое пользователем значение не должно быть предложено больше него (можно молча зажимать или явно сказать «максимум 500»).
- **Лимит отправки** (`rate_limit_per_min`, R62) — число.
- **Ретеншн** (`retention_days`, R68) — число дней.

Ввод чисел — с проверкой (не число / отрицательное / ноль там, где не имеет смысла → понятная ошибка на русском, не падение). Каждое изменение — сразу пишет в `settings` через `SettingsRepo.update`, короткое подтверждение («✅ Сохранено: 14 дней»).

## Критерии приёмки

- [ ] Пункт «⚙️ Настройки» виден в главном меню, ведёт в список из шести пунктов
- [ ] Каждый пункт показывает текущее значение перед вводом нового
- [ ] Тумблеры (`monitor_all_dm`, `dedup_enabled`) переключаются одним нажатием
- [ ] Числовые поля (`dedup_window_days`, `scan_days`, `scan_msgs`, `rate_limit_per_min`, `retention_days`) отклоняют нечисловой/отрицательный ввод понятной русской ошибкой, не падают
- [ ] `scan_msgs` не может быть выставлен выше `HARD_MSG_CAP` (500) — либо зажимается, либо явно отклоняется с объяснением
- [ ] Новый шаблон подписи реально влияет на следующую собранную карточку (`build_card`)
- [ ] Все изменения читаются обратно из `SettingsRepo` после сохранения (round-trip тест)
