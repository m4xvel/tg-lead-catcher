tg-lead-catcher

Telegram-лидогенератор: userbot ловит сообщения по ключевым словам в выбранных чатах и пересылает их в целевой чат с карточкой автора — всё управление через бота-панель, без правки кода.

Готово

Проверено независимой слепой приёмкой — запуском проекта, а не пересказом кода.

Userbot слушает выбранные группы/супергруппы/каналы (личные чаты — по флагу), ловит слово/фразу/regex-ключи без учёта регистра и «ё/е», отсекает минус-словами. Найденное пересылается форвардом (с фолбэком на копию, если чат запрещает пересылку) во все приёмники, следом идёт карточка автора со ссылкой на профиль и на оригинал сообщения. Дедуп двойной — по id сообщения всегда, по автору+тексту за настраиваемое окно. Правки сообщений и альбомы обрабатываются целиком.

Вся настройка — источники, приёмники, ключевые слова, минус-слова, шесть параметров устойчивости (окно дедупа, глубина догона, лимит отправки, ретеншн, шаблон карточки, личные чаты) — через кнопки бота-панели, ни одной правки в коде не требуется. Кнопка «🧪 Проверить» показывает, сработает ли текст, до реального запуска. Статус, статистика за 7/30 дней, топ мусорных ключей, история из 50 срабатываний, экспорт настроек в JSON — всё на месте.

Устойчивость: очередь доставки в SQLite с тремя попытками и растущей задержкой, глобальный лимит отправки, корректная обработка FloodWaitError, а при смерти Telegram-сессии — немедленное уведомление владельцу через резервный канал (Bot API), не через саму умершую сессию.

Запустить

# установка
pip install -e ".[dev]"

# первый раз — мастер настройки: создаёт .env, логинит обе Telethon-сессии
python configure.py

# через Docker (рекомендуется для постоянной работы)
docker compose up -d

# либо локально, двумя процессами
python -m userbot.main
python -m panel.main

Обе команды — docker build и pip install -e — реально проверены вживую двумя независимыми ревьюерами, не просто прочитаны в коде.

Что пошло не по плану

Четыре места, где сборка доказала, что план был неточен — требование то же, изменился способ.

Слово-ключ технически ловит и «ремонтник», и «автора»

Твой собственный пример в брифе — «"авто" не ловит "автора"» — на практике не выполняется: правило «по началу слова», которое и даёт нужное «ремонт» → «ремонтник», без морфологического анализа (а его ты сам исключил) не может одновременно не ловить «авто» → «автора». Это один и тот же механизм для обоих случаев — развести их нечем. Минус-слова закрывают большинство ложных срабатываний на практике.

Regex-ключи не получают ё/е-эквивалентность

Первая версия применяла ё→е-замену и к regex-паттернам — ревью поймало баг: замена превращала \D в \d, ломая смысл выражения на противоположный. Regex-ключ теперь компилируется как есть, только с re.IGNORECASE; для ё/е в своём regex — пиши [ёе] сам.

Точки входа не были в изначальном плане

Тикеты собрали все модули (приём, доставка, панель), но ни один не собирал их в реально запускаемый процесс — обнаружилось на ревью последнего тикета. Закрыто отдельным тикетом.

userbot и панель не могут делить один файл Telethon-сессии

Слепая приёмка нашла: оба процесса читали/писали один файл сессии — известный риск повреждения при двух одновременных процессах. У панели теперь своя, отдельно логинящаяся сессия того же аккаунта.

Открытые вопросы

Слепая приёмка сначала нашла настоящий дрейф — шесть требований (окно дедупа, глубина догона, лимит отправки, ретеншн, шаблон карточки, флаг личных чатов) реально работали только через прямую запись в базу, без элемента UI, хотя манифест считал их готовыми. Плюс не собирался Docker-образ и падал pip install (конфликт имени setup.py с инструментами упаковки Python). Все восемь — закрыты: тикет панели настроек добавил недостающий UI, инфраструктурный тикет починил сборку и перенос TZ из .env в реальную настройку.

Осталось непроверенным вживую (нет реального Telegram-аккаунта для проверки): сам вход через python configure.py, реальная пересылка сообщений, реальный FloodWaitError, задача Планировщика Windows. Логика каждого проверена тестами с фейковым Telegram-клиентом — что происходит на реальном аккаунте, увидишь при первом запуске мастера.
