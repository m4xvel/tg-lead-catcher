## Что должно заработать

Слепое использование после сдачи нашло баг: в разделе «⚙️ Настройки» при попытке изменить шаблон подписи пользователь передумал и отправил `/start`, ожидая выйти из режима ввода. Вместо этого `/start` сохранился как новое значение `card_template` буквально — карточки доставки после этого стали бы собираться с текстом `/start` вместо шаблона с плейсхолдерами, никакой ошибки при этом не было (нашли только по случайно открытому меню настроек).

**Причина.** Хендлеры, ожидающие свободный текст в состоянии FSM, регистрируются только по фильтру состояния, без исключения текста, похожего на команду — WHERE любое сообщение, включая `/start`/`/export`/что угодно с `/`, долетает до хендлера как «введённое значение». Это один и тот же паттерн в шести местах:

| Файл | Состояние | Хендлер | Есть кнопка «Отмена»? |
|---|---|---|---|
| `panel/settings.py:168` | `SettingsStates.waiting_value` | `on_settings_value` | нет |
| `panel/keywords.py:212` | `KeywordStates.waiting_bulk` | `on_bulk_text` | нет |
| `panel/keywords.py:215` | `KeywordStates.waiting_check_text` | `on_check_text` | нет |
| `panel/sources.py:524` | `AddChatStates.waiting_manual` | `on_manual_text` | есть (`kb.cancel_kb`) |
| `panel/sources.py:525` | `AddChatStates.waiting_forward` | `on_forward` | есть (`kb.cancel_kb`) |
| `panel/sources.py:520` | `AddChatStates.waiting_search` | `on_dialog_search_text` | есть (`kb.cancel_kb`) |

Нужно почистить это в двух частях (обсуждено и подтверждено пользователем):

**1. Команда во время ожидания ввода = тихая отмена, во всех шести местах.** Если `message.text` начинается с `/` (любая команда — `/start`, `/export`, что угодно ещё) — значение не сохраняется, не проверяется, не добавляется. FSM state очищается, пользователь тихо возвращается в тот вид, куда его вернула бы кнопка «Отмена» этого же потока (список настроек / список ключей / список источников-приёмников). Без отдельного «❌ Отменено» — так же тихо, как уже работает `on_cancel_add` в `panel/sources.py`. Команду саму по себе повторно никуда не прокидывать (не пытаться, скажем, ещё и выполнить `/start` как команду) — обычной отмены достаточно, пользователь при необходимости повторит команду или нажмёт нужную кнопку меню сам.

Это шесть похожих, но раздельных проверок в начале каждого хендлера — не заводить ради этого общий модуль/миксин между `panel/settings.py`, `panel/keywords.py`, `panel/sources.py`: эти модули уже осознанно независимы (см. `panel/__init__.py` и границы владения в CLAUDE.md), а проверка в одну строку не оправдывает межмодульную связь.

**2. Кнопка «‹ Отмена» — в трёх потоках, где её сейчас нет.** `panel/sources.py` (ручной ввод / пересылка / поиск по диалогам) уже показывает `kb.cancel_kb(target)` при входе в ожидание — этот паттерн трогать не нужно, только добавить туда пункт 1. Добавить такую же кнопку в:

- **Настройки** (`panel/settings.py:on_settings_edit_start`) — оба варианта промпта (текстовый шаблон и числовое поле) сейчас показываются без клавиатуры вообще. Нужна `SettingsCancelCB` (без полей) в `panel/keyboards.py` + `settings_cancel_kb()` (по образцу `cancel_kb`), хендлер `on_settings_cancel` — очищает state, зовёт тот же `_render_menu`, что и `cmd_settings_menu`.
- **Ключи/минус-слова, построчный ввод** (`panel/keywords.py:on_add_start` → `waiting_bulk`) — использовать существующее понятие `target` (`TARGET_KEYWORD`/`TARGET_STOPWORD`), например `KeywordCancelCB(target: str)` + `keyword_cancel_kb(target)`, хендлер очищает state и зовёт `render_keyword_list(..., target=target, keywords=keywords)` — тот же вид, что и после обычного добавления.
- **Проверка текста** (`panel/keywords.py:on_check_start` → `waiting_check_text`) — здесь нет списка, куда возвращаться (`on_check_text` сейчас просто отвечает результатом, ничего не перерисовывает); кнопка отмены должна просто прервать ожидание ввода (очистить state) без результата проверки.
