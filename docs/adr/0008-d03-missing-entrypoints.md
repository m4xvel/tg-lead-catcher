# 0008. D03 — точки входа не были частью изначального плана тикетов

## Контекст

План тикетов (02–05) строил модули: `userbot`, `panel`, `matcher`, `store`,
`worker`. Предполагалось, подразумеваемо, что после сборки всех модулей
`docker-compose.yml` и Планировщик Windows (R11, R65) смогут реально запускать
процессы этими модулями.

## Решение

Сборка показала: ни один из тикетов 02–05 не создал исполняемые точки входа
(`python -m userbot.main`, `python -m panel.main`) — все они строили модули, но
не оболочку процесса вокруг них. Заведён отдельный тикет 07 постфактум, чтобы
закрыть разрыв.

## Почему

Рассмотрено и отклонено — считать, что точка входа неявно входила в один из
существующих тикетов (например, в тикет 04 «панель: каркас/чаты» или в тикет
02 «userbot: приём/матчинг»): по факту сборки ни один из них файл запуска не
создавал, значит такое предположение плана было ошибочным, а не просто
неявным, и полагаться на него дальше нельзя.

## Последствия

R11 (переносимость через Docker/`.env`) и R65 (автозапуск) формально не могли
считаться выполненными до отдельного тикета 07 — модули существовали, но
запускать было нечем. Любой похожий план на будущее должен явно включать
тикет на точки входа процессов, а не полагаться на то, что «собрать модуль»
автоматически подразумевает «сделать его исполняемым».
