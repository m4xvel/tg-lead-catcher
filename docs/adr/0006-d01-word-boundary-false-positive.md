# 0006. D01 — правило «начало слова» не разводит «ремонтник» и «автора»

## Контекст

План (spec.md §3) предполагал, что правило `\b<ключ>\w*` без морфологии
(сознательно исключённой по R72) закроет R17 полностью: ловить словоформы
(«ремонт» → «ремонта», «ремонтник»), не ловя подстроку внутри другого слова
(брифовый контрпример — «авто» не должно ловить «автора»).

## Решение

Сборка доказала: то же самое правило, которое обязано ловить «ремонтник» по
ключу «ремонт», механически ловит и «автора» по ключу «авто» — оба случая
неотличимы одним regex-правилом без словарной информации о границах морфем.
Оставлено как есть, по букве §3, без исправления.

## Почему

Рассмотрен и отклонён вариант «граница слова с обеих сторон» (`\bключ\b`, без
хвоста `\w*`): это убрало бы ложное срабатывание на «автора», но заодно сломало
бы нужное срабатывание на «ремонтника» — то есть решило бы D01 ценой прямого
нарушения приёмки R17.

Рассмотрен и отклонён вариант с морфологическим анализом, который развёл бы
случаи по словарю форм: явно исключён брифом (R72), это заведомо не вариант
для данной сборки.

## Последствия

Единственный доступный пользователю инструмент против таких коллизий —
минус-слова, добавляемые вручную под конкретный ложный кейс (например,
минус-слово «автора» при ключе «авто»), а не точность самого правила
матчинга. При добавлении новых коротких ключей стоит ожидать похожих
коллизий систематически, а не считать их багом, который однажды исправят.
