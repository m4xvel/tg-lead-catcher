# tg-lead-catcher

Бот, который сам следит за нужными Telegram-чатами и присылает вам сообщения,
где встретились ваши ключевые слова — с указанием автора и ссылкой на
оригинал. Например: мониторите чаты объявлений на ключ «сдам квартиру» —
как только кто-то написал такое сообщение, оно тут же прилетает вам в личку
или в отдельный чат-приёмник.

Вся настройка — через обычное меню Telegram-бота, кнопками. Программировать
и трогать код не нужно.

> Однопользовательский инструмент: настраивается на одного владельца и один
> Telegram-аккаунт. Для команды или нескольких аккаунтов не подойдёт.

## Что нужно, прежде чем начать

1. **Обычный Telegram-аккаунт** (номер телефона), от имени которого бот
   будет читать чаты. Это не отдельный бот-аккаунт, а именно ваш — как если
   бы вы сами сидели в этих чатах.
2. **Свой Telegram-бот** для панели управления — создаётся бесплатно за
   минуту у [@BotFather](https://t.me/BotFather), нужен только токен.
3. **Компьютер или сервер**, на котором всё будет постоянно работать
   (ноутбук ночью выключать нельзя — бот перестанет ловить сообщения).
   Подойдёт свой ПК, недорогой VPS или что угодно с Docker.
4. Установленный **[Docker Desktop](https://www.docker.com/products/docker-desktop/)**
   (самый простой способ запуска) либо **Python 3.11+**, если хотите без
   Docker.

## Установка

### Шаг 1. Скачать проект

```bash
git clone <адрес вашего репозитория> tg-lead-catcher
cd tg-lead-catcher
```

### Шаг 2. Установить зависимости

```bash
pip install -e ".[dev]"
```

### Шаг 3. Настроить и войти в аккаунт

```bash
python configure.py
```

Это интерактивный мастер, который запускается один раз. Он спросит по
очереди:

| Что спросит | Где взять |
|---|---|
| `API_ID`, `API_HASH` | [my.telegram.org](https://my.telegram.org) → войдите по своему номеру → «API development tools» → создайте приложение (имя любое) → скопируйте оба значения |
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) в Telegram → `/newbot` → придумайте имя и username → в ответ пришлёт токен вида `123456789:AA...` |
| `OWNER_ID` | Ваш числовой Telegram ID. Узнать у [@userinfobot](https://t.me/userinfobot) — перешлите ему любое сообщение или напишите `/start` |
| `TZ` | Часовой пояс для отметок времени, можно просто нажать Enter (по умолчанию `Europe/Moscow`) |

Дальше мастер попросит код подтверждения из Telegram (придёт как сообщение
от «Telegram») и, если включена двухфакторная аутентификация, пароль.
Это выполняется **дважды** — вход делается сразу в две независимые сессии
(userbot и панель), это нормально и безопасно: как если бы вы одновременно
открыли Telegram Desktop и Telegram Web.

Все секреты сохраняются в файл `.env` у вас на диске и никуда не
отправляются — `configure.py` не подключается ни к чему, кроме официального
Telegram API.

### Шаг 4. Запустить

Самый простой способ — через Docker:

```bash
docker compose up -d
```

Готово. Оба процесса подняты и будут сами перезапускаться, если упадут или
если перезагрузится компьютер.

Без Docker — см. раздел [«Для разработчиков»](#без-docker).

### Шаг 5. Открыть панель

Напишите своему боту (тому, чей токен вы указали на шаге 3) команду
`/start`. Он ответит только вам — это и есть ваша панель управления.

## Как этим пользоваться

Всё управление — кнопками в чате с ботом-панелью. Главное меню:

- **📥 Источники** — чаты, каналы или группы, которые нужно мониторить.
  Добавить можно тремя способами: выбрать из списка своих чатов, переслать
  боту любое сообщение из нужного чата, или ввести `@username`/ссылку
  вручную. У каждого источника — переключатель «поставить на паузу» и
  кнопка удаления.
- **📤 Приёмники** — куда присылать найденное: личный чат, «Избранное»,
  канал или группа. Добавляются так же. Можно указать несколько.
- **🔑 Ключевые слова** и **🚫 Минус-слова** — что искать и что
  игнорировать. Вводятся списком, по одному на строку. Кнопка
  «🧪 Проверить» позволяет вставить произвольный текст и сразу увидеть,
  сработает ли он.
- **⚙️ Настройки** — мониторить ли личные переписки (по умолчанию нет),
  окно и включение повторного дедупа по автору и тексту, шаблон подписи
  под пересланным сообщением, лимиты ручного скана истории.
- **📊 Статистика** — включён ли мониторинг, сколько источников/приёмников/
  ключей, что в очереди на отправку, топ «шумных» ключей, история последних
  50 срабатываний, кнопка `/export` — выгрузить все настройки в JSON-файл.
- **⏸/▶️** — общий выключатель: остановить или возобновить мониторинг, не
  трогая сами процессы.

Когда в источнике находится сообщение с вашим ключевым словом, бот
пересылает его в приёмник(и) и следом отправляет карточку: кто автор
(кликабельная ссылка) и ссылка на оригинал сообщения.

## Синтаксис ключевых слов

| Тип | Как ввести | Что делает |
|---|---|---|
| Слово | `ремонт` | Ловит слово в любом падеже и слова, начинающиеся с него (например, поймает и «ремонтник») |
| Точная фраза | `ищу подрядчика` | Ловит именно эту фразу целиком |
| Регулярное выражение | `re:\d{3}-\d{2}` | Для тех, кто знает regex — гибкий поиск по шаблону; при вводе проверяется на корректность |

Всё регистронезависимо, «е» и «ё» считаются одной буквой (кроме
регулярных выражений — там это могло бы сломать сам шаблон).

Минус-слова работают точно так же, но отменяют срабатывание: если в
сообщении есть и ключ, и минус-слово — оно не будет доставлено.

## Как это работает внутри

Два процесса работают вместе и делят общую папку с данными:

- **userbot** — незаметно читает чаты от вашего имени (никакого токена бота
  ему не нужно), сравнивает текст с ключевыми словами и рассылает находки в
  приёмники.
- **panel** — обычный Telegram-бот, через который вы всё настраиваете.
  Сам ничего не пересылает, только читает и записывает настройки.

```
Сообщение в источнике
        │
        ▼
  userbot видит его вживую
        │
        ▼
  проверка: не пауза / не бот / не своё / не чат-приёмник
        │
        ▼
  сверка с ключевыми и минус-словами
        │
        ▼
  проверка на дубликат (по id сообщения, опционально — по автору+тексту)
        │
        ▼
  постановка в очередь на отправку
        │
        ▼
  доставка во все приёмники (с ограничением скорости и повтором при сбое)
```

Если форвард запрещён владельцем исходного чата, бот автоматически
присылает текст копией — ни одно совпадение не теряется.

## Ежедневная эксплуатация

- Все данные (база и Telegram-сессии) лежат в папке `./data` — именно её
  нужно бэкапить.
- Записи о срабатываниях хранятся 90 дней, потом чистятся автоматически.
- Полезные команды Docker:

  ```bash
  docker compose logs -f          # смотреть логи в реальном времени
  docker compose restart          # перезапустить после смены .env
  docker compose down             # остановить (данные в ./data сохранятся)
  docker compose up -d --build    # пересобрать после обновления кода
  ```

- Если хотите автозапуск на Windows без Docker — готовый скрипт для
  Планировщика заданий: [`deploy/windows-task.md`](deploy/windows-task.md).

## Перенос на сервер (VPS)

Хотите, чтобы бот работал круглосуточно без вашего компьютера — перенесите
его на недорогой VPS (Ubuntu 22.04/24.04 с Docker):

```bash
curl -fsSL https://get.docker.com | sh
```

Дальше — либо настройте с нуля прямо на сервере (повторите шаги
[«Установка»](#установка) там), либо скопируйте с рабочей машины всю папку
проекта вместе с `./data` и файлом `.env` (он не попадает в git, его нужно
перенести отдельно):

```bash
rsync -avz --exclude '.git' ./ user@your-vps:/opt/tg-lead-catcher/
ssh user@your-vps "cd /opt/tg-lead-catcher && docker compose up -d"
```

Если переносите (а не держите две копии одновременно) — не забудьте
остановить локальный `docker compose down`, чтобы старая сессия не мешала
новой.

## Если что-то пошло не так

- **Панель пишет «Доступ запрещён»** — вы пишете не с того аккаунта; в
  `.env` должен стоять именно ваш числовой `OWNER_ID`
  ([узнать через @userinfobot](https://t.me/userinfobot)), не username.
- **Бот вообще не отвечает** — процессы не запущены. Проверьте
  `docker compose ps` и `docker compose logs`.
- **Пришло сообщение о «смерти сессии»** — Telegram разлогинил userbot
  (например, из-за смены пароля аккаунта). Запустите `python configure.py`
  заново, затем включите мониторинг обратно кнопкой в панели.
- **Ожидаемое сообщение не пришло** — проверьте по очереди: источник не на
  паузе, общий тумблер включён, ключ действительно матчит текст (кнопка
  «🧪 Проверить»), сообщение не попало под минус-слово, это не повтор от
  того же автора в окне дедупа.
- **Ошибка при добавлении regex-ключа** — шаблон некорректен с точки зрения
  Python `re`; текст ошибки в панели подскажет, что поправить.

## Чего тут нет — сознательно

- Нескольких аккаунтов/владельцев (не мультиарендный инструмент).
- Веб- или десктоп-панели — управление только через Telegram-бота.
- Разных наборов ключей на разные источники — набор один, общий.
- Морфологического анализа слов — правило «начало слова» иногда ловит
  лишнее (например, «авто» поймает и «автора»).
- Полнотекстового поиска по старой истории (доступны только последние 50
  срабатываний).
- Автоответов лидам, рассылок, автовступления в чаты.

## Для разработчиков

<a name="без-docker"></a>

**Запуск без Docker** (нужен Python ≥ 3.11):

```bash
pip install -e ".[dev]"
python configure.py       # один раз
python -m userbot.main    # в одном терминале
python -m panel.main      # в другом
```

**Технологии:** Telethon (MTProto-клиент userbot), aiogram 3 (Bot API
панели), SQLite через aiosqlite, pytest + pytest-asyncio.

**Тесты:**

```bash
python -m pytest                                    # весь набор
python -m pytest tests/matcher/test_ruleset.py -q    # один файл
python -m pytest tests/worker/                       # один модуль
```

Сеть и реальный Telegram в тестах не используются: `matcher` тестируется
чистыми функциями, `store` — на временной SQLite, `userbot`/`panel` — через
фейковый Telethon-клиент.

**Структура проекта:**

```
matcher/    компиляция ключевых слов в правило совпадения — без Telegram и БД
store/      схема SQLite и репозитории по сущности
userbot/    Telethon-сессия: приём сообщений, догон истории, доставка
worker/     фоновая очередь доставки, рейт-лимит, ретраи, ретеншн
panel/      Telegram-бот управления: меню, мастера ввода, статистика
tests/      зеркалит структуру пакетов выше
deploy/     автозапуск без Docker на Windows
docs/adr/   архитектурные решения (ADR)
```

Подробнее об архитектуре, границах модулей и внутренних соглашениях кода —
в [`CLAUDE.md`](CLAUDE.md).
